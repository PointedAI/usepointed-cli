---
title: Interview templates
description: Create reusable interview plans and prepare links for selected accounts or contacts.
---

Interview templates are reusable collection plans. The CLI command remains `story-templates`. Enrollment prepares links for contacts; it does not send customer email or start a call.

<Note>
  Starters, product/channel/length options and whole-account enrollment shortcuts are in the upcoming 0.5.0 source version. npm currently publishes 0.4.0. [Run from source](/docs/installation#run-from-source) to use the new options.
</Note>

## Create from a use case

```bash
pointed story-templates starters
pointed story-templates create --starter roi-stories --product "Your product" --interview-length quick
```

A starter supplies its title, goal, opening approach and default length. Options you provide override those defaults. `--product` is an alias for `--product-name`. `--interview-length` accepts `quick` (about 2–3 minutes), `standard` (4–6) or `deep` (7–10). Choose the participant experience with `--interview-channel`.

| Value | What participants can do |
| --- | --- |
| `phone` | Take the interview by phone. |
| `browser` | Join on the web and decide whether to turn on their camera. |
| `browser_audio` | Join on the web with voice only. |
| `browser_video` | Join on the web after consenting to camera and audio recording. |
| `participant_choice` | Choose phone or web. On the web, the camera starts off. |

Existing invitations keep their saved options.

Without a starter, supply a title and goal. The respondent role defaults to `Account stakeholder`, and a custom initial question is optional:

```bash
pointed story-templates create \
  --title "Renewal proof" \
  --customer-facing-name "ROI story" \
  --role "Economic buyer" \
  --goal "Capture ROI stories before renewal" \
  --initial-question "What changed after adopting the product?"
```

Use `--customer-facing-name` for the interview name shown to participants and `--customer-facing-topic` for what you want to hear about. Both options work with `story-templates create` and `story-templates update` in the source CLI. For example, use the topic “how onboarding went for your team.”

## Inspect templates

```bash
pointed story-templates list
pointed story-templates get <templateId>
pointed story-templates enrollment-options <templateId>
```

## Enroll an account

```bash
pointed story-templates enroll <templateId> \
  --account-id <accountId> \
  --auto-include-new-contacts
```

Enroll specific contacts:

```bash
pointed story-templates enroll <templateId> \
  --account-id <accountId> \
  --contact-emails jane@acme.example,sam@acme.example
```

Omitting both contact selectors includes all contacts on the account. Explicitly empty selectors, including empty shell variables, are rejected. Supply either `--contact-ids` or `--contact-emails`, not both.

## Enroll whole accounts

```bash
pointed story-templates enroll <templateId> --account-ids accountA,accountB
```

To include every account in the current workspace, explicitly use:

```bash
pointed story-templates enroll <templateId> --all-accounts
```

These modes include everyone on the selected accounts. Choose either `--account-ids` or `--all-accounts`; they cannot be combined with single-account/contact selectors or a JSON selection body. An empty account list is rejected. Omitting both auto-include flags inherits the template default for a newly enrolled account. An already enrolled account keeps its existing choice. Use `--auto-include-new-contacts` to opt in or `--no-auto-include-new-contacts` to opt out explicitly.

For spreadsheet-based enrollment of just the file's people, use [account import with `--enroll`](/docs/account-imports#import-and-prepare-interviews).

## Manage enrollment

```bash
pointed story-templates account <templateId> <accountId>
pointed story-templates set-auto-include <templateId> <accountId> --enabled false
```

`autoIncludeNewContacts` controls whether newly created contacts on an enrolled account receive prepared, unsent interview links. Neither enrollment nor auto-add sends invitations.

```bash
pointed story-templates enroll <templateId> --account-id <accountId> --no-auto-include-new-contacts
```

In the app, **Interview settings → People → Auto-add new people** sets the default for future account enrollments. Saving a change to this template-wide switch also replaces the auto-add choice on every currently enrolled account. The account's Templates card and `set-auto-include` can override that choice afterward; another change to the template-wide switch replaces those overrides again. Enabling it does not retroactively enroll existing contacts.

The CLI has no dedicated template-wide switch command. Use the app to change the template-wide default. The opt-out enrollment flag is available in the upcoming 0.5.0 source version; npm 0.4.0 users can pass `"autoIncludeNewContacts": false` in an enrollment JSON body or use `set-auto-include` for an existing enrollment.

## Edit settings and review existing interviews

The app's Interview settings page saves the name, goal, length, participant channels, opening question, product context and guidance. Choose **Web interview** and set whether the camera is optional, required, or off. Choose **Participant’s choice** to also offer phone. When the camera is optional, the participant can turn it on and review the video recording notice before continuing. Older templates offering phone and web voice keep that selection until you change it. Changes to interview content offer a review of eligible unstarted interviews: save the template alone to preserve existing invitations, or select the unstarted interviews to update. Accepted or started interviews keep their frozen settings. A concurrent edit keeps your draft and asks you to load the saved version before retrying.

Auto-add by itself affects future contact enrollment, so it does not require an unstarted-interview review. A template-wide auto-add change still replaces the per-account choices described above.

## Test a saved template and open its results

In the app, open **Interview settings → Test**. On a template with no recipients, you can also choose **Test it yourself**. The dialog prepares a private interview using the last saved settings. Save any draft changes you want to hear first.

For a video test, review the recording notice and confirm consent before allowing camera and microphone access. Web voice tests use only your microphone. You can mute or end the test in the dialog. A phone-only template can be previewed in the browser when web voice is available. This previews the questions and depth. Testing the phone connection itself requires a phone test.

**View results** opens the private test result. For video, keep the tab open until the upload finishes. Pointed can then process the recording in the background. Test runs use the workspace’s test allowance and stay out of customer Results. To see real interviews from the template, open it and choose **Results**. Clear the template filter to see other customer interviews.

## Read interview statuses

The app groups the saved states into Not sent, Sent, In progress, Completed, Didn't finish and Expired, with Removed shown separately. Partial responses appear under **Didn't finish**, not Completed. These are display groups; the CLI continues returning the original backend states, so scripts should keep handling those states.

Recipients counts and status matches load in pages. A `+` means a count is still loading; it becomes exact after all pages arrive. The completed-interview count excludes test/demo and moderated results. An account or contact can match more than one status when it has multiple interviews. Historical completions remain counted after a contact is removed, although that contact no longer appears in the directory.

## Legacy imports

```bash
pointed story-templates legacy-import-summary
pointed story-templates import-legacy
```

Legacy import creates interview templates for eligible existing campaigns and attaches the existing campaign records. It does not send new customer email.
